# Niki Product Completion

Dynamic harness contract for finishing the live product backlog and final evaluation.

## Objective

Finish the live product backlog and final evaluation; do not claim perfection, skip blocked work, or start Rust before the gate.

## Inputs

- current branch
- `docs/niki/CHECKLIST.md`
- `docs/niki/PROGRESS.md`
- `docs/niki/OWNER_VERIFY.md`
- `docs/superpowers/plans/2026-11-23-niki-agent-architecture.md`
- relevant package `AGENTS.md`
- `docs/niki/workflow-state.json`

The controller is `libs/code/scripts/niki_workflow.py`. Run it from `libs/code`; `status` and `next` are read-only.

## Task card

Produced by `niki_workflow.py next` and containing:

- item ID/title
- exact source requirement
- files
- test name and command
- acceptance result
- owner/branch
- dependencies
- known blocker

## Loop

1. Discover current state with `status` and `next`.
2. Select one eligible item and claim it with `start`.
3. Write a failing behavior test named by the card.
4. Implement one slice behind the existing port/event boundary.
5. Run focused test, lint, and type checks; save the step with `step`.
6. Obtain an independent review of the diff.
7. Update checklist, progress, and state; call `finish` only with WORKS evidence and the full commit SHA.
8. Commit before selecting the next item.
9. Return the evidence and next item.

Use `.agents/skills/architecture-patterns/SKILL.md` (pinned in `skills-lock.json`) only when a backlog item changes a port or adapter: dependencies point inward, domain and application contracts stay framework-free, and use-case tests need no Docker, network, or model key.

## Status view

Show the current phase, queue, active task/saved step, checklist and evaluation gate status, blocker or latest evaluation result, owner/branch, last commit, and handoff fields. Blocked items stay visible and cannot be claimed until `unblock` records a resolution and the item passes a retest.

## Stop conditions

- failing checks
- overlapping ownership or a second simultaneous claim
- unresolved product decision
- unavailable owner-only evidence
- missing credentials/runtime at the final evaluation
- any attempted `libs/deepagents` change
- Rust work before the Python readiness and matched benchmark gates pass

## Handoff

Report status, item ID, commit, changed files, exact checks and results, evidence links, blocked items, and next item. Never create another top-level plan for an item generated by this loop.
